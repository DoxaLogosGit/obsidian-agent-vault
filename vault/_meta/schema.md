# Agent Operational Schema

Full operational rules for AI agents working in this vault. The vault root `AGENTS.md` is the concise version (the root `CLAUDE.md` only imports it); this document is authoritative on edge cases and design rationale.

---

## Design Principles

These are non-negotiables. Every skill written under this plan must respect them.

**1. Vault is domain-primary.** Top-level folders are life domains, listed in `_meta/vault-config.yml`. Active projects live at `Projects/<domain>/<project>/`. Categories like `concepts/`, `entities/` may exist *within* a project if useful, but are never imposed at the vault root or across projects.

**2. Underscore directories are excluded zones.** Any `_`-prefixed directory is skipped by ingest scanning/routing/topic-matching and never listed as note content in indexes; its `.md` files stay valid wikilink targets so inbound links from audited notes resolve. Write access differs by dir: `_sources/` is **read-only** — a human-controlled drop zone read as ingest *input*, agents never write/rename/delete inside it. Pure-reference `_`-dirs are **read-only** — not an ingest source, not a routing target, not audited, cited only. `_meta/` is the **writable operational store** (the exception) — agent-owned operational files live here (indexes, logs, `last-ingest.md`, design-log, ignored-uuids), while still being excluded from note scanning/routing/content-indexing.

**3. Ownership is data, not folder structure.** Every note carries an `owner` frontmatter field. Notes without the field are treated as `owner: shared` — this default means existing notes don't need backfill before skills can run.

**4. Provenance is preserved, not implied.** Claims in agent-touched notes are marked using the obsidian-wiki convention (verbatim — solved problem):
- Default (no marker) = extracted, paraphrased from source
- `^[inferred]` = LLM synthesis beyond what source states
- `^[ambiguous]` = sources disagree or source is unclear

**5. Skills are read-cheap.** Adopt the retrieval cost hierarchy: index → frontmatter `summary:` → grep → full read. Cite this hierarchy in skill docs rather than reinventing it.

**6. No silent rewrites.** Lint reports issues. It does not auto-fix. The human decides what to fix.

**7. Design log is mandatory.** Every non-obvious decision made while implementing a skill gets a one-sentence entry in `_meta/design-log.md`.

## Ownership Model

| `owner` value | Agent behavior |
|---|---|
| `human` | Read and cite only. If modification is requested, output a diff and stop. Let the human merge manually. |
| `agent` | Update freely. Fully agent-managed. |
| `shared` (default) | Update freely, but preserve sections the human clearly authored. Lint flags issues; does not rewrite. |

Heuristic for identifying human-authored sections in `owner: shared` notes: sections without `^[inferred]` or `^[ambiguous]` markers that have no corresponding claim in any listed source.

---

## Provenance Convention

| Marker | Meaning |
|---|---|
| _(none)_ | Extracted or paraphrased from a named source |
| `^[inferred]` | LLM synthesis or generalization beyond what sources state |
| `^[ambiguous]` | Sources disagree or the source itself is unclear |

The `provenance:` frontmatter block summarizes the distribution across a note:

```yaml
provenance:
  extracted: 0.85
  inferred: 0.12
  ambiguous: 0.03
```

Fractions should sum to ~1.0. Lint flags deviations >10%.

## Frontmatter Convention

Minimum for notes that participate in skill operations:

```yaml
---
title: Note Title
owner: shared           # human | agent | shared (default if absent)
tags:
  - project-tag
sources:
  - _sources/chat-2026-04-15-slug.md
updated: 2026-04-27T00:00:00Z
---
```

Optional fields:

```yaml
summary: One-line preview ≤200 chars. Used by retrieval hierarchy (cheaper than full read).
provenance:
  extracted: 0.85
  inferred: 0.12
  ambiguous: 0.03
```

Notes without frontmatter are handled gracefully: treated as `owner: shared`, no provenance assumptions, `summary:` unavailable (fall back to grep).

### `sources:` entry forms

Either a flat string or a mapping. New ingests always write the mapping form; flat strings are legacy and upgraded on first ingest touch.

```yaml
sources:
  - _sources/legacy.md                  # flat: path only, no change tracking
  - path: _sources/chat-2026-04-15.md   # mapping: tracked by content hash
    sha256: abc123…
  - path: _sources/deleted-input.md     # retired: file deliberately deleted
    sha256: def456…
    retired: true
```

**`retired: true`** means the source file was intentionally deleted after ingest. Because `sources:` is append-only, the entry stays as the permanent lineage record — the hash is retained so the note's derivation is still identifiable. `obsidian-lint-light` skips the stale and drift checks for retired entries and reports them under an informational `Retired sources` count that does not add to the issue total.

Retire with `obsidian-ingest/retire_sources.py _sources/<file> [...] [--apply] [--delete]` (dry run by default) **before** deleting the files. `--delete` removes each file after its entries are retired. `--scope <project>` retires a whole stray `<project>/_sources/` directory instead. Retirement reads each file to capture its hash, which is the last chance to record it. This is the one sanctioned exception to "upgrade flat `sources:` strings only on ingest touch."

### `status:` values

`active`, `planning`, `decided`, `reference` — plus `superseded` (decision replaced; keep the note as the historical record and add `superseded_by:`), `revised` (still current but materially amended), and `needs-rewrite` (content known stale, but no updated source exists to ingest from). Nothing validates against this list; it is a shared vocabulary, not an enum.

## Retrieval Cost Hierarchy

When reading vault content to answer questions or make edits, prefer cheaper operations first:

1. `index.md` in the project or `_meta/index.md`
2. Note frontmatter `summary:` field (one-line, fast scan)
3. `grep` with context for specific terms
4. Full note read — only when the above are insufficient

## Skills

### Phase 1 (current)

**`obsidian:ingest`**
Reads a Claude Desktop conversation export already placed by the human in `_sources/` and creates or updates a derived project note.
- Reads from `_sources/<file>` — never writes to `_sources/`
- Creates or updates derived note in the appropriate project folder (e.g. `Projects/<domain>/<project>/`)
- Respects `owner` field: refuses human-owned notes (outputs diff instead), updates agent/shared freely
- Marks claims with provenance markers; updates `sources:` and `updated:` frontmatter
- Appends to `design-log.md` only if a non-obvious decision was made

**`obsidian:lint-light`**
Read-only audit. Never modifies any file.
- Broken wikilinks, orphan sources, stale sources
- Malformed frontmatter, unknown `owner` values, provenance fractions that don't sum to ~1.0
- Provenance drift (recomputes from note content, flags if >10% off frontmatter)
- Inferred-claim audit list for human spot-check
- Output: `_meta/lint-report-<timestamp>.md`

### Phase 2 (build only when friction is felt)

| Skill | Trigger |
|---|---|
| `manifest-track` | Re-ingesting becomes expensive or duplicative |
| `wiki-query` | grep-and-read stops being sufficient for finding things |
| `cross-link` | Manually maintaining wikilinks across notes becomes a chore |
| `ingest-pdf` / `ingest-article` | Non-chat source ingestion becomes regular workflow |
| `lint-rebuild-from-sources` | Provenance audit (regenerate from sources, diff current) becomes worth the cost |

## What Is Explicitly Out of Scope

- Global category system (`concepts/`, `entities/` at vault root)
- Global graph view layer (Obsidian's native graph is sufficient)
- MCP tooling
- Auto-fix for lint (read-only is the contract)
- Telemetry or phone-home of any kind

## Inherited Patterns

| From | What | Why |
|---|---|---|
| obsidian-wiki / Karpathy | `^[inferred]` / `^[ambiguous]` / default-extracted | Solved problem. Renders cleanly. Don't reinvent. |
| obsidian-wiki | Retrieval cost hierarchy | Production-grade design. Cite it, don't redesign. |
| Karpathy gist | Three-layer conceptual model | Used as principle, not folder structure. |
| obsidian-wiki | `provenance:` frontmatter block | Cheap to compute, valuable for lint. |

## Rejected Patterns

| From | What | Why |
|---|---|---|
| All implementations | Strict LLM ownership of derived layer | Doesn't match shared-edit workflow |
| All implementations | Top-level `raw/` directory | Sources colocate per-project |
| obsidian-wiki | Category-primary organization | Domain-primary chosen instead; project nesting lives under domains |
| obsidian-wiki | Auto-rewrite on lint | Read-only is the contract |

# Obsidian Vault — Agent Instructions

This is a personal Obsidian vault. Notes are authored collaboratively — both human and agent edit project notes. This is a working quasi-wiki, not a compiled/LLM-owned knowledge base.

## Organization

The top-level note folders are listed in `_meta/vault-config.yml`. `writable_roots` holds the folders that ingest may write to. `_meta/` at the vault root holds cross-project metadata and operational files.

[[Vault Map]] at the vault root is the human-facing version of this list. Update it when a top-level folder or domain changes.

Raw source files (chat exports, PDFs, articles) all live in **one** place: `_sources/` at the vault root. They are immutable — never modified after being placed there. Nothing at the vault root is restructured by skills or agent operations.

## Ownership Model

Every note carries an `owner` frontmatter field. Notes without it are treated as `owner: shared`.

| Value | Meaning |
|---|---|
| `owner: human` | Read and cite only — **never modify** |
| `owner: agent` | Fully agent-managed; update freely |
| `owner: shared` | Agent edits freely; lint flags issues rather than auto-fixing |

When asked to modify a `owner: human` note: output a diff of what you would have changed and stop. Let the human decide.

## Provenance Convention

Claims in agent-touched notes are marked inline:

- No marker = extracted or paraphrased from source (default)
- `^[inferred]` = LLM synthesis beyond what the source states
- `^[ambiguous]` = sources disagree or source is unclear

Always mark inferred claims. Never silently synthesize beyond source material.

## Retrieval Cost Hierarchy

Prefer cheaper reads before expensive ones:

1. **`_meta/index.md`** — vault-wide master index, every note grouped by folder with a one-line summary. Start here when you don't know which folder a topic lives in.
2. **`<folder>/index.md`** — per-folder index inside any folder containing notes. Same wikilink + summary format. Use this once you know the project/folder.
3. Note frontmatter `summary:` field — when an index entry tells you the note exists but you need slightly more before reading.
4. `grep` with context — when you're looking for a specific term, quote, or symbol that wouldn't appear in a summary.
5. Full note read — only when steps 1–4 narrowed the target.

**Grep scope:** an ignore-aware search tool (`grep`, `rg`) run plain from the vault root finds the notes that git tracks. It also floods the results with raw sources and operational files. Use `rg -n "pattern" -g '!**/_*/**' .` — the glob excludes underscore-prefixed dirs (`_sources/`, `_meta/`, etc.) at any depth without hardcoding a folder list. Add `--no-ignore` only to search inside `.gitignore`d paths on purpose.

**Indexes are agent navigation aids, not just human-facing.** Every folder under the `audited_roots` in `_meta/vault-config.yml` that contains notes has an `index.md` regenerated by `obsidian-ingest` on every ingest and by `obsidian-lint-light --rebuild-indexes`. Read the index *before* grepping. A skill that greps the vault to find a note that the index would have surfaced in one read is doing it wrong, and a skill that opens a 500-line note to extract 15 lines is a bug.

Indexes are `owner: agent` and fully regenerated each run — never hand-edit them; if an entry is wrong, fix the underlying note's `summary:` and re-run the ingest or lint.

## Conciseness

Be terse. Both in chat and in notes.

- **Chat:** answer directly. Skip restating context already established, narrating options you won't take, or summarizing what you're about to do before doing it.
- **Ingested notes:** paraphrase tight. Capture the load-bearing claims — decisions, reasoning that mattered, concrete facts — and drop illustrative exposition or blow-by-blow narration that doesn't add information. Complete, not exhaustive.
- Provenance markers still apply — a shorter note with accurate `^[inferred]`/`^[ambiguous]` markers beats a longer one that repeats itself.

### Prose Rules

Adapted from ASD-STE100 Simplified Technical English. These apply to note bodies and to chat. The full standard lives in the `simple-english` skill — invoke it for genuinely procedural writing (runbooks, install steps, how-to sections), not for every note.

- **Sentences:** one topic each, 25 words or fewer. Split anything longer. No semicolons — write two sentences.
- **Voice:** active. Use passive only when the actor is genuinely unknown.
- **One word, one meaning,** per note. Pick `check` or `verify` or `confirm` and keep it. Synonym rotation reads as variety and lands as ambiguity.
- **Conditions before commands,** with a comma: "If the hash differs, write a date-stamped file."
- **Noun chains:** three words maximum. Break longer ones with prepositions — "the timeout value for the connection pool", not "the connection pool timeout value".
- **Delete words that carry no fact:** simply, seamlessly, robust, powerful, comprehensive, leverage, "in order to", "it is worth noting". Replace `utilize` with `use` and `prior to` with `before`.
- **Vertical lists** for more than two items or steps.
- **Warnings:** the command or condition first, then the risk. "Do not run this against production. The command deletes rows."

**The modal verbs are deliberately exempt.** ASD-STE100 bans *should, would, may, might, could* and tells you to write `must` or delete. Do not apply that rule here. This vault's provenance convention depends on those words — "the source may be wrong on this date" is a precise claim, and `^[ambiguous]` exists to mark exactly that kind of hedge. Forcing `must` would overstate; deleting would lose the uncertainty the marker is pointing at. Keep the hedge the source earned.

Never apply any of this to quoted source material, code blocks, identifiers, file paths, or error messages. Those are reproduced verbatim.

## Underscore Directories Are Excluded Zones

Any directory whose name starts with `_` is excluded from note operations: skipped by ingest scanning/routing/topic-matching and never listed as note content in indexes. Their `.md` files remain valid wikilink targets (notes may link into them), but agents never treat them as ingest or routing targets.

Whether agents may **write** to a `_`-dir depends on the dir:

- `_sources/` (vault root, the only one) — **create-only.** Human-controlled drop zone for raw inputs (chat exports, PDFs, articles); read as ingest **input**. Agents never modify, rename, or delete anything inside it. Agents may create a new file only when fetching a source the human asked for, and only at a path that does not already exist. Ingest itself never writes here — fetching is a separate operation (`obsidian-ingest/fetch_export.py` for Claude exports, `obsidian-ingest/fetch_youtube.py` for YouTube transcripts). Deleting an already-ingested source is a deliberate operation with a tool: retire the `sources:` entries first (`obsidian-ingest/retire_sources.py`) so the content hash survives, then remove the file.
- Pure-reference `_`-dirs — **read-only.** Not an ingest source, not a routing target, not audited — cited only, never modified.
- `_meta/` — **writable operational store** (the exception): agent-owned operational files live here (indexes, logs, `last-ingest.md`, design-log, ignored-uuids). Still excluded from note scanning, routing, and content-indexing.

## Published Works Stay Out

Do not ingest the text of a published work. This covers game rulebooks, manuals, books, and articles, whether they arrive as a PDF in a chat export, a file in `_sources/`, or a paste in a conversation. Record what the vault needs instead: the title, the edition, the decision that was made, and the page or section that settles a rule.

Rulebooks the human writes are the human's own work, and they are fine to hold.

Attachments in a chat export follow the same rule. Images never enter the vault, and a PDF is read only when the human approves that file.

## No Silent Rewrites

Lint skills report issues. They do not auto-fix. The human decides what to fix. This is non-negotiable for `owner: shared` notes — auto-rewriting human edits is a vault corruption failure mode.

## Skills Available

Skills live in `.agents/skills/<name>/SKILL.md` and follow the Agent Skills spec (agentskills.io). Codex and OpenCode read `.agents/skills/`. Claude Code reads the same files through the `.claude/skills` symlink. If your tool does not load skills, read the `SKILL.md` before you ingest or lint, and follow it. Some steps name Claude Code tools, such as subagent dispatch. Do the same work with your own tools, or do it inline.

Keep `skills/` together as one directory, inside the vault. The scripts find the vault root and each other by paths relative to their real location.

- `obsidian:ingest` — ingest any source already in the vault-root `_sources/` (Claude export `.json`/`.zip`, `.md`, `.html`, `.pdf`) and create or update notes with provenance markers. Auto-detects the source type and routes vault-wide, prompting for anything unmatched. Takes no arguments except `--status` and `--files-backlog` (backfills files from chats ingested before 2026-09-14)
- `obsidian:youtube` — fetch YouTube transcripts into `_sources/` with `fetch_youtube.py`, then run ingest. Takes one or more URLs, plus `--lang` and `--fetch-only`
- `obsidian:lint-light` — read-only audit: broken wikilinks, orphan sources, stale sources, malformed frontmatter, provenance drift
- `obsidian:status` — print the time of the last ingest. Same as `obsidian:ingest --status`
- `obsidian:files-backlog` — backfill chat files into conversations ingested before file support. Same as `obsidian:ingest --files-backlog`
- `obsidian:retire` — retire and delete ingested sources in `_sources/` with `retire_sources.py`, so the folder does not grow without limit. Takes optional file names. Without them, it lists the candidates
- `obsidian:fetch-export` — place a Claude data export from `~/Downloads` into `_sources/` with `fetch_export.py`. The user downloads the zips in a signed-in browser. The agent never fetches the links

## Frontmatter Convention

Minimum for notes that participate in skill operations:

```yaml
---
owner: shared           # human | agent | shared (default if absent)
sources:                # relative to project folder, optional
  - _sources/chat-2026-04-15-slug.md
updated: 2026-04-27T00:00:00Z
---
```

Optional fields when relevant:

```yaml
summary: One-line preview ≤200 chars, used by retrieval hierarchy.
provenance:
  extracted: 0.85
  inferred: 0.12
  ambiguous: 0.03
```

## Backup and Version Control

If the vault is a git repository, agents follow these rules:

- Do not commit or push unless the human asks.
- Do not run `git clean`, `git reset --hard`, or `git checkout -- .` in this vault. Uncommitted human edits from Obsidian live in the working tree.
- Do not create a symlink whose target resolves outside the vault.
- One symlink is allowed: `.claude/skills` → `../.agents/skills`. It is relative and stays inside the vault. Do not add others without the human's approval.
